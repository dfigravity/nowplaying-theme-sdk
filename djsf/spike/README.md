# Renderer spike (2026-10-06)

Built in a scratch clone of upstream `nowplaying-theme-sdk` (475e322) with `pixi.js@8.22.0`.

- `index.tsx`: a theme that mounts a Pixi 8 Application at 384×216 (`backgroundAlpha: 0`, nearest
  sampling, `roundPixels`), CSS-scales the canvas by the largest integer that fits, imports
  `sheet.png` and draws a two-frame sprite plus a BitmapText ticker that shows the track.
- `sheet.png`: 64×32 two-frame placeholder generated by script (no art).
- `sf-spike.np3theme`: the resulting bundle. `shared/entry.js` is 1,350,649 bytes (332 KB gzip) and
  contains the PNG as a `data:image/png;base64` URI. Not yet uploaded to NP3 or rendered in a browser.

Two SDK changes were required (patch in `../docs/sdk-assets-and-dynamic-imports.patch`):
1. `scripts/theme-meta.mjs`: the meta reader's esbuild pass had no loader for relative image imports,
   so any theme importing a PNG failed the build. The stub plugin now stubs non-code relative imports
   (images, fonts, json, audio, raw text) the same way it stubs CSS.
2. `vite.bundle.config.ts`: `inlineDynamicImports: true`. Pixi picks its renderer with dynamic
   imports; Vite library mode emitted them as separate chunks and `build-bundle.mjs` copies only
   `entry.js`, so the bundle shipped a 30-byte stub.

Size note: with everything inlined the bundle carries WebGL, WebGPU and Canvas renderers. Importing
`WebGLRenderer` directly instead of `Application`/`autoDetectRenderer` should drop the WebGPU code.
